## Findings

### P1-1: execute-round skill contract puts audit-check in the wrong phase

**Location**: `skills/execute-round/SKILL.md:42-46`

**Evidence**:

- Skill doc says Phase 3 runs `mypy / pytest / ruff / audit-check`.
- Same doc says Phase 4 only composes/writes/commits the self-audit handoff.
- Implementation places audit-check after composing the Phase 4 self-audit handoff: `toolkit/src/arcgentic/skills_impl/execute_round.py:577-599`.
- `docs/tech-debt.md:19` closes ER-AUDIT-GATE-4 with evidence that Phase 4 runs `audit_check.run(..., strict_extended=True)`.

**Impact**: The user-facing skill is the operator contract. It currently describes a workflow that cannot be literally true because `audit-check` needs the self-audit handoff that Phase 4 creates. This is a core workflow contract contradiction.

**Minimal fix**: Update `skills/execute-round/SKILL.md` so Phase 3 runs only `mypy / pytest / ruff`, and Phase 4 composes self-audit handoff, runs `arcgentic audit-check --strict-extended`, then commits state + audit.

### P1-2: generated self-audit footer has stale release version

**Location**: `toolkit/src/arcgentic/skills_impl/execute_round.py:331`

**Evidence**:

- Header uses `arcgentic v0.2.2-alpha.1` at line 235.
- Footer still says `arcgentic v0.2.1-alpha.1` at line 331.
- Manifest/toolkit/docs all declare `0.2.2-alpha.1`.

**Impact**: Every generated self-audit handoff from this release will carry contradictory version evidence. Because audit artifacts are fixed evidence, stale release metadata is not cosmetic.

**Minimal fix**: Replace the stale footer literal with `v0.2.2-alpha.1` or derive it from `arcgentic.__version__`; add a focused regression assertion that generated self-audit text contains no `v0.2.1-alpha.1`.
